# 유지보수 런북 (관리자용)

이슈 신고를 받아 수정 릴리스를 내기까지의 표준 절차입니다.
파이프라인 상세와 스크립트는
[SeochoBatang-Making](https://github.com/iwantanid/SeochoBatang-Making)
저장소를 참조하세요.

## 버전 규칙

- 글리프 수정·버그픽스: **v1.0.1, v1.0.2 …** (패치)
- 글자·기호 추가, 지표 변화: **v1.1, v1.2 …** (마이너)
- 굵기 추가 등 패밀리 확장: **v2.0** (메이저)

## 핫픽스 절차 (목표: 접수 후 1시간 내 릴리스)

### 1. 재현

신고된 글자를 현재 배포 TTF로 크게 렌더링해 증상을 확인한다.
신고 환경(HWP/Word/웹)과 크기도 함께 재현한다. 재현이 안 되면
스크린샷과 렌더를 비교해 환경 요인(구버전 설치 잔존, 앱 캐시,
대체 폰트 표시)을 먼저 의심한다 — 이 경우 수정 없이 안내로 종결.

### 2. 분류

| 유형 | 판별 | 조치 |
|---|---|---|
| 생성 글리프 결함 | 해당 글자가 모델 생성분(실물 채집 목록에 없음) | TTA 재추론으로 재생성 (Making: `sweep3_model_defects.py`의 수리 경로) |
| 실물 글리프 결함 | 채집분 (파편·트레이스 문제) | 원본 비트맵에서 재트레이스, 파편은 연결성분 필터로 제거 (`retrace_real_c.py`) |
| 기호 결함 | 원문자·도형 등 | `fabricate_symbols.py`에서 해당 글자만 재제작 |
| 빌드·테이블 문제 | 특정 앱에서만 증상 (설치 거부, 폰트 전환 등) | name/OS-2/cmap 테이블 점검 후 재빌드 |

### 3. 수리 후 검증 (필수)

- 수리 글자 + 주변 유사 글자 확대 렌더 육안 확인
- 고정 검수 3자(흥·훙·홍) 포함 스팟 시트 렌더
- 파편·갈라짐 스캔을 수리 글자에 대해 재실행 (0이어야 통과)

### 4. 재빌드

Making 저장소에서:

```bash
python scripts/v15_chain.py    # 빌드→수직보정→패키징→QA 일괄
```

- 출력 경로는 `SC_OUT` 환경변수로 지정 (기존 설치본이 파일을
  잠글 수 있으므로 버전 접미사 파일명 사용)
- QA 전 항목(구조/커버리지/오버레이/Word) 통과 확인

### 5. 릴리스

1. 이 저장소의 `fonts/`에 새 TTF/WOFF2 복사, name 테이블 버전 갱신
2. 커밋 메시지에 수정 글자와 이슈 번호 명시 (`fix #12: '뷁' 잔점 제거`)
3. 태그·릴리스 생성:

```bash
gh release create v1.0.1 SeochoBatang-v1.0.1.zip fonts/SeochoBatang-Regular.ttf --title "서초바탕 v1.0.1" --notes "수정: ..."
```

4. 이슈에 수정 버전과 확인 방법을 회신하고 닫는다.

### 6. 기록

수리 내역을 릴리스 노트에 남기고, 반복되는 유형이면 Making 저장소의
검수 스크립트에 해당 패턴 탐지를 추가한다 — 같은 신고를 두 번
받지 않는 것이 목표.

## 대응 우선순위

1. **P0 — 문서가 깨지는 문제** (설치 불가, 특정 앱에서 폰트 전환,
   글자 누락·tofu): 당일 대응
2. **P1 — 글자 품질** (획 이상, 잔점, 위치): 1~3일 내 패치 릴리스
3. **P2 — 개선 요청** (볼드체, 기호 추가): 수요를 모아 마이너 버전에
   반영. 동일 요청 누적 수를 이슈 라벨로 추적

## 알려진 내부 과제 (신고 전 선제 파악용)

- 극단적 밀집 글자(뾺류)의 속공간이 10pt 이하 인쇄에서 좁아질 수 있음
- 한자 41자는 원본과 달리 전각 고정폭
- 로마숫자 Ⅷ~Ⅻ의 자간이 다소 넓음
